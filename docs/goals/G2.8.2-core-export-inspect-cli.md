# G2.8.2 — Core archive export and inspect CLI

Status: implementation

Issue: [#55](https://github.com/cosZone/koharu-suite/issues/55)
Parent: [G2.8 portable archive](./G2.8-portable-archive.md)

## Outcome

G2.8.2 is the first production consumer of `@koharu-suite/archive-format`. It adds a synchronous
point-in-time metadata export and a database-independent inspector:

```text
kodama archive export --output /safe/path/archive.tar.zst \
  [--channel -1001234567890]... [--include-provenance] [--overwrite] [--json]

kodama archive inspect --input /safe/path/archive.tar.zst [--json]
```

The archive carries canonical channels, public and hidden messages, every immutable revision,
Telegram entities, media metadata, and any known verified original-media identity. It never carries
media bytes in this Goal. Strict portable provenance is opt-in.

## Data boundary

Exported data is identified only by Telegram Chat ID, Telegram Message ID, revision number, and the
typed source identity frozen in archive format v1. Internal UUIDs, raw Telegram JSON, Desktop source
paths, HTML, renderer state, search/RSS output, cache backend locations, Owner/Auth rows, audit rows,
credentials, allowlist state, and deployment configuration are excluded.

Every selected read and count is produced inside one PostgreSQL read-only `REPEATABLE READ` snapshot.
The repository invokes a record sink while the transaction is alive; iterators never escape the
transaction. A session advisory try-lock allows one export at a time and returns a stable busy error
instead of waiting. The lock covers snapshot reading, archive construction, validation, and publication;
it is released before the run evidence is moved to its terminal state. Inspect does not acquire that lock
and never opens PostgreSQL.

Canonical families use stable keyset pages. Provenance families use transaction-scoped PostgreSQL
server-side cursors so their mapping CTE and sort execute once per family instead of being repeated for
every page. An export cancellation signal also calls `pg_cancel_backend` for the active snapshot session,
so a blocked or long-running database statement is interrupted rather than merely abandoned by Node.js.

Records are ordered exactly as required by the v1 validator:

1. channel by Chat ID;
2. message by Chat ID and Message ID;
3. revision by message identity and revision number;
4. revision media by revision identity and position;
5. provenance observation by message/revision identity and typed source identity;
6. provenance media by observation identity and position.

The exporter validates each mapped record, reconciles streamed counts against the snapshot, then
builds bounded JSONL shards. A complete archive is validated again before publication.

## Artifact safety

The destination parent must already exist, resolve to a real directory owned by the current effective
user, and not be group/world writable. Every ancestor must be root/current-user owned and either not
group/world writable or protected by the sticky bit. The exporter keeps the parent directory open,
records its device/inode identity, and rechecks the path and handle before staging, validation,
publication, and cleanup. This is the explicit trust boundary used instead of adding a native `openat`
dependency.

Staging happens in that directory with generated names, `0700` work directories, and `0600` files.
The archive is written, fsynced, closed, reopened with no-follow/non-blocking flags, and fully inspected
before it is visible at the requested name. Default publication uses a hard link for atomic no-clobber;
explicit overwrite uses same-filesystem rename only after rejecting symlink and special-file leaves.
The parent directory is fsynced after publication.

Failures and cancellation delete only generated staging state. If publication succeeds but the parent
fsync fails, the result is `finalization_durability_unknown`: the complete final artifact is preserved for
operator inspection rather than guessed away.

## Reports and evidence

`archive inspect` returns the frozen archive-format report and its `0 clean / 2 partial / 1 fatal` exit
mapping. Export uses a separate server-side v1 report envelope. With `--json`, stdout contains exactly
one JSON object followed by one newline; progress and diagnostics use stderr.

Both archive subcommands reject extra positionals and options that do not belong to that subcommand.
Even argument-parser failures preserve the versioned one-object JSON stdout contract when `--json` was
requested. Stdout completion is awaited, and a closed downstream pipe fails cleanly without an unhandled
stream error or an absolute-path stack trace.

`archive_export_runs` records bounded operational evidence only: logical selection, provenance flag,
format/schema versions, lifecycle state, snapshot time, artifact hash/length, sanitized report, and
timestamps. It never stores host paths, record bodies, credentials, database URLs, or account data.
The run is created before output preflight and lease acquisition, so an unsafe destination or concurrent
export attempt still reaches a terminal failed/interrupted state instead of disappearing from evidence.
Durable browser transfer jobs, leases, retries, resumable uploads, TTL, and artifact ownership remain
G2.8.5.

## Non-goals

- media blob reads or `--include-media`;
- import, staging, conflict resolution, or apply;
- time-range selection;
- transfer APIs and Owner Desk;
- built-in encryption or signing.

## Verification gate

- unit tests for CLI/reporting, safe file publication, offline inspect, cancellation, and injected I/O faults;
- PostgreSQL 18 integration for canonical/provenance mapping, selection, counts, and concurrent snapshot writes;
- workspace lint, typecheck, unit/integration tests, build, package/runtime and Compose smoke checks;
- security and logic re-review with all important findings repaired before PR acceptance.
