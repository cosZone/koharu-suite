# G3.1 — Owner Desk 重设计(行动收件箱)

> GitHub Issue:—(待补)｜ 日期:2026-07-25 ｜ 状态:Implemented(分支 feat/owner-desk-redesign)
> 设计原型:`.artifacts/owner-desk-directions/c-triage/index.html`(静态五屏,含内容清单 `BRIEF.md`)

## 1. 背景与问题

Owner Desk(`apps/admin`)当前是单页七板块长页(统计 → 消息 → 搜索 → 运维台 → 媒体缓存 →
对账 → 安全),样式为两份手写 CSS(`apps/admin/src/styles.css` 1781 行 +
`packages/ui/src/styles.css`),无设计 token、无组件交互原语(`window.confirm` 充当确认层,
原生 `<select>`/自定义 toggle 充当控件)。2026-07-25 的全页分析确认三个信息架构问题:

1. **待办散落**:阻塞任务、开放 finding、缓存失败分处三个面板,Owner 需滚四屏才能拼出
   "我现在要处理什么";唯一需要立即行动的队列不在首屏。
2. **消息详情缺上下文**:`selectedMessage` 可被归档列表与搜索结果双向写入,面板不显示
   频道归属,从搜索跳入时与 rail 选中频道脱节。
3. **反馈通道不统一**:错误有三条通道(页顶 `page-error`、面板内 feedback、表单内),
   页面底部操作失败时错误出现在视口外;"必填审计原因"三处交互不一致;加载态与空态
   不区分(消息列表首载期间误显"这个频道还没有归档消息。")。

## 2. 目标与非目标

### Goals

- 按**方向 C(行动收件箱)**重排 IA:「需要处理」(跨板块聚合待办,置顶)→
  「系统脉搏」(纯只读监控)→「浏览与工具」;频道列表改为页头下横带。
- 全量引入 **Tailwind CSS v4 + shadcn/ui**(组件 copy 进 `apps/admin`),Radix 原语
  接管 Switch/Select/Dialog 等交互;`@koharu-suite/ui` 从 admin 依赖中退役。
- 建立单一来源的**设计 token 体系**(Tailwind `@theme` CSS 变量):深色冷中性底、
  强调色单变量可换、圆角上限 4px、标题衬线 + Inter 正文。
- 顺带修复 §1 三个 IA 问题。
- 状态覆盖:常态 / 空 / 加载(skeleton,与空态区分)/ 错误(就地)/ 2FA 全流程。
- 6 处 `window.confirm` 全部替换为 AlertDialog,确认文案逐字保留。
- 测试契约显式更新并全绿;`pnpm --filter @koharu-suite/admin` 的
  test / typecheck / build 通过。

### Non-Goals

- `apps/server` 任何改动;API 端点、字段、校验规则、轮询逻辑保持不变。
- 新功能(新操作、新数据、新路由)、浅色主题(token 结构预留,不交付)、i18n 框架。
- 删除 `packages/ui` 仓库目录(仅解除 admin 对它的依赖;包去留另起收尾)。
- 行为契约变化:reason 必填规则、分页 cursor、搜索短词守卫、raw no-store 等全部照旧。

## 3. 约束与假设

- 硬视觉约束(来自评审基线,违反即返工):深色底冷中性色;禁止渐变;禁止 box-shadow
  作为层级手段(层级 = 1px 边框 + 背景明度差 + 字号字重);圆角 ≤ 4px;标题一种衬线、
  正文 Inter;**每屏最多一个强调色使用点**,状态用文字而非颜色表达;禁止 emoji 图标。
- 现有测试(`media-cache-panel.test.tsx`、`reconciliation-panel.test.tsx`、
  `search-and-feeds-panel.test.tsx`)是 `renderToStaticMarkup` 字符串断言,构成语义契约:
  `aria-labelledby`/`aria-label`/`role="status"`/`name="search-*"`/RSS `href`/
  placeholder/关键文案/**负向断言**(不得出现 `telegramFileId`、`blobs/`、bucket 名、
  未转义 `<mark>`)。新结构允许更新断言,但负向断言与表单 `name` 契约必须原样保留,
  更新须在 PR 中逐条说明。
- 文案全部沿用现有中文原文,不改写;新增 chrome(区块名等)另行评审。
- React 19、Vite、pnpm workspace、better-auth 会话流程不变;部署 base `/admin/` 不变。
- shadcn/ui 采用 copy-in 模式(`apps/admin/src/components/ui/`),不新增发布物。

## 4. 方案设计

### 4.1 设计 token(单一来源,Tailwind v4 `@theme`)

| token | 值 | 用途 |
|---|---|---|
| `--background` | `#0A0D11` | 页底 |
| `--card` / `--popover` | `#10151B` | 抬升面 |
| `--inset` | `#07090C` | 凹陷/输入底 |
| `--border` | `#1E242C` | hairline |
| `--input` | `#2A313A` | 强线 |
| `--foreground` | `#E8EBEF` | 正文 |
| `--secondary-foreground` | `#E8EBEF` | 次级面上的文字 |
| `--muted-foreground` | `#A3ACB8` | 次级文字 |
| `--faint` | `#6B7480` | 最弱文字(自定义 slot) |
| `--primary` | `#8FB8FF` | **唯一强调色,换主题色只改这一个变量** |
| `--destructive` | `#E0635B` | 语义错误红,仅错误元素 |
| `--ring` | `#8FB8FF` | 焦点环 |
| `--radius` | `0.25rem`(4px 上限) | 全局限 |

- 字体:`--font-sans: Inter, 'PingFang SC', …`;`--font-serif: Fraunces, 'Noto Serif SC', serif`
  (标题用);数字 `font-feature-settings: "tnum"`。
- 状态语义去颜色化:成功/在线/已启用一律文字表达,不上绿色;警告不使用琥珀/橙。
- Google Fonts 链路同原型;无渐变、无阴影、无圆角超 4px 的工具类出现。

### 4.2 信息架构(方向 C)

屏序:登录(双步骤)→ 主面板三个区块 → 其余状态由区块内组件承载。

- **页头**:品牌、Collector 状态(唯一位置,删除运维台 runtime 重复处的 Worker 状态行,
  runtime 版本/心跳保留在系统脉搏区)、`退出`。
- **频道横带**(页头下方):全部频道横排,当前频道文字下划线;承担"浏览过滤"职责。
- **区块目录**:三个区块名 + 各行数/待办数,锚点跳转。
- **需要处理**:聚合大数字 + 统一条目(来源标签 QUEUE/FINDING/CACHE/RENDER +
  标题 + meta + 操作原因输入 + 操作按钮)。来源:阻塞任务 retry/skip、finding
  repair/ignore/hide/unhide、缓存对象 retry、待重渲染 rerender。审计契约说明置顶。
  每条目操作后从队列消失(乐观更新逻辑不变)。
- **系统脉搏**(纯只读,无按钮):10 项统计、Collector runtime、缓存用量/计数、
  后端卡、最近维护命令、最近运行、最近失败。
- **浏览与工具**:消息主从浏览(列表 + 详情)、搜索与 RSS 订阅出口、写工具
  (频道启停 Switch、批量复制、LRU 整理、媒体缓存对账、运行安全扫描)、账号 2FA。
- **消息详情上下文修复**:详情头部固定显示所属频道名 + 发布时间;从搜索结果跳入时
  同步高亮频道横带对应频道,并标注来源(消息来自 `Message.channel`,不再隐式脱节)。

### 4.3 组件策略(Tailwind v4 + shadcn/ui)

现状 → 目标映射:

| 现有 | 目标 |
|---|---|
| `@koharu-suite/ui` Button/Input/Badge | shadcn `button`/`input`/`badge`(badge 用 outline,状态纯文字) |
| Field(label+error 关联) | shadcn `label` + 自组 Field(保留 `aria-describedby`/`aria-invalid` 关联) |
| Panel/PanelHeader | 区块内以 hairline/Separator 分区;Card 仅用于写工具与账号 |
| EmptyState | 迁入 admin 自组(与 Skeleton 明确区分) |
| Kicker | 删除,区块标签用文字 |
| 自定义频道 toggle | shadcn `switch`(`role="switch"`,修正键盘语义) |
| 原生 `<select>` | shadcn `select`(Radix,键盘/ARIA 完整) |
| 6 处 `window.confirm` | shadcn `alert-dialog`,确认文案逐字保留 |
| 无加载态 | shadcn `skeleton`(消息列表/统计/需要处理区首载) |
| 容量 `<progress>` | shadcn `progress` |
| 三条反馈通道 | **统一规则:错误就地 inline(`role="alert"`,出现在操作所在条目/表单旁);成功/入队回执一律 sonner `toast`;取消页顶 `page-error`** |

依赖:`tailwindcss@4` + `@tailwindcss/vite`、`class-variance-authority`、`clsx`、
`tailwind-merge`、`radix-ui`(或按组件拆包)、`sonner`、`lucide-react`(**不引入**,
遵守禁图标约束;shadcn 组件默认图标处改文字/留空)。`components.json` 手写,
不跑交互式 init。

### 4.4 IA 修复对照

| 问题 | 措施 |
|---|---|
| 待办散落三屏 | 需要处理区聚合队列置顶,三面板待办合一,操作入口就地 |

### 4.5 状态覆盖

常态之外,每区块显式设计:空态(沿用现有全部空态文案)、加载(skeleton 行,
禁止用空态文案冒充)、错误(就地 + 重试入口)、忙碌(按钮文案沿用 `正在…` 系列)、
2FA 未启用/设置中(secret + 恢复代码)/已启用三形态。

### 4.6 测试契约更新

- 保留:全部负向断言(脱敏红线)、`name="search-*"`、RSS `href`、placeholder、
  搜索守卫逻辑(`shortQueryGuard` 纯函数不动)、消毒白名单。
- 更新:面板标题断言改为区块结构断言(如 `aria-labelledby="lane-triage-title"`);
  逐条在 PR 说明映射关系。
- 新增:需要处理区聚合渲染断言(不同来源条目同队列)、finding 原因未填时按钮 disabled。

### 4.7 退役路径

`apps/admin` 移除 `@koharu-suite/ui` 依赖与两份旧 CSS import;`packages/ui`
(含 Storybook)本期保留不动,后续单独 Goal 决定删除或改造。

## 7. 实施记录(2026-07-25,分支 feat/owner-desk-redesign)

## 9. 路由化与固定壳层(2026-07-26)

评审反馈"侧栏锚点应是不同页面而非页内跳转,且左侧与顶部应固定、内容区独立滚动":

- **错误归位**:`actionError` 从两个区块细化为页面键

  轮询错误留在固定壳层(全局可见)。
- 新增文件:`desk-context.ts`(Desk 类型 + `useDesk`)、`pages.tsx`(8 个页面)。
  组件层(TriageLane/MessageBrowser/各卡片)零改动复用;18/18 测试、
  typecheck、build、lint 全绿。
