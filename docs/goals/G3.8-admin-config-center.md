# G3.8 — Admin 配置中心(设置页环境变量管理)

> 日期:2026-07-25 ｜ 状态:Implemented

## 前置

- G3.1 Owner Desk 已完成路由化,设置页(`/admin` → 设置)已存在,可承载新板块。
- 非敏感配置此前只能改 `.env` 并重启,owner 无法在面板内调整;S3 等能力上线后,改配置
  需要登录宿主机,运维成本高。
- `config_overrides` 表由迁移 `apps/server/drizzle/0021_mighty_marrow.sql` 建立
  (`key`/`value`/`updated_at`/`updated_by`)。

## 背景

媒体缓存、S3、公开 API、采集并发等非核心配置全部走环境变量。对单一 owner 的自托管部署而言,
每次调整都要编辑 `.env` 并重启 server 与 worker,且容易留下 partial config。本 Goal 在
Admin 设置页提供配置中心:owner 可在面板内修改白名单内的配置项,落库为 override,
下次启动时与 shell 环境变量、`.env` 按明确优先级合并。

## 范围

- **配置注册表** `apps/server/src/config-registry.ts`:4 个分区(媒体缓存 / S3 存储 /
  公开 API / 采集)共 20 个可配置 key,每项带 label、描述、zod schema 与 secret 标记;
  分区之外的变量(数据库、Bot token、`BETTER_AUTH_*` 等)不可从面板修改。
- **启动合并** `apps/server/src/cli.ts`:`serve`/`worker`/`media` 启动时读取
  `config_overrides` 并合并,优先级为 **显式 shell 环境变量 > DB override > `.env`**。
  合并只在启动时发生一次:面板保存后必须重启 server 与 worker 才生效,UI 以
  `pendingRestart` 提示待生效状态。
- **API** `GET/PUT /api/v1/admin/config`:GET 返回分区、当前生效值、来源
  (`default`/`override`/`explicit_env`)与锁定状态;PUT 仅接受 owner session
  (service token 403),`reason` 必填,写入 `operation_audit_events`
  (action `config.update`)。
- **锁定**:启动时显式设置的 shell 环境变量锁定对应面板字段,UI 显示
  「由环境变量锁定」,PUT 对该 key 返回拒绝。
- **secret 只写**:`S3_KEY`/`S3_SECRET` 保存后永不回显;GET 与 UI 只暴露
  是否已配置 + 末四位(last4);审计 details 只记录 key 名与 set/unset 标记,
  不记录 secret 值。
- **doctor**:`kodama doctor` 报告 override 数量、被显式环境变量锁定的 key、
  以及 override 表读取失败(降级为 warn,环境配置继续生效)。

## 验收

- 设置页按分区展示 20 个配置项,保存后落库 `config_overrides`,重启后生效。
- 显式 shell 环境变量优先于面板 override,并锁定对应字段无法编辑。
- S3 core settings 的 all-or-none 等跨字段校验在 PUT 时按启动语义复用,不合法的
  组合被拒。
- secret 值不出现在 GET 响应、UI 与审计 details 中。
- PUT 必须 owner session 且 `reason` 必填,审计记录完整。

## 验证命令

```bash
pnpm --filter @koharu-suite/server test
pnpm --filter @koharu-suite/admin test
pnpm typecheck
pnpm exec kodama doctor
```

手测:设置页修改 `MEDIA_CACHE_DOWNLOAD_CONCURRENCY` → 保存(填原因)→
`config_overrides` 出现该 key → 重启 server/worker 后生效;`S3_KEY` 保存后 GET
仅返回 last4;显式 `export S3_BUCKET=...` 重启后该字段锁定。

## 文档影响

- `docs/media-cache/README.md` / `README.en.md` 配置段注明面板配置入口、
  重启生效语义与优先级;脱敏契约补充面板 secret 只写规则。
- `.env.example` 在可面板配置的变量组上方注明面板入口与锁定/优先级规则。

## 明确不做

- 非白名单变量(数据库、`BETTER_AUTH_*`、Bot token、频道)不从面板修改。
- 不做热更新:所有变更显式要求重启,不做运行时 reload。
- 不做配置历史/回滚 UI(审计事件已含 before/after 标记,历史查询另案)。
- 不做多 owner 协同、审批流或配置导入导出。
